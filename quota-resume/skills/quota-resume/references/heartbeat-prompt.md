# 建立時填入具體內容，之後保存完整文字到 automation prompt

quota-resume:<實際任務ID>

這是使用者已啟用的「額度恢復接續」，只在本任務接續以下已授權工作。

工作目標：<具體且有邊界的目標>
完成條件：<可核實的完成條件>
工作位置：<實際工作區或來源>
既有約束：<使用者已指定的必要約束>
建立時進度：<已完成步驟與尚待完成事項，不含敏感資料>
週用量停止門檻（已使用百分比）：<填入 1–100 的數值，未指定時為 70>
適用用量 bucket：<建立時確認的 limitId；若之後無法辨識則停止本次工作，不猜測>

每次排程開始，先確認使用者最新指示、近期結果與必要的工作紀錄。使用者已取消、明確暫停、或完成條件已達成時，找出標記 quota-resume:<實際任務ID> 的這個排程，透過 automation_update 將它設為 PAUSED，保留其他欄位；完成停用後回報一次結果。若無法停用，要明確指出失敗，不能假稱已停止。不要將建立時進度當成最新狀態。

使用 get_usage_limits 讀取目前用量。usedPercent 是已使用百分比，優先查看適用的 rateLimitsByLimitId；缺少資料是未知。五小時與每週等所有適用視窗都必須可用；已超過 resetsAt 仍不代表服務已更新額度。若仍耗盡、狀態未知或暫時連線失敗，結束本次嘗試並讓下次排程處理，不要在同一回合密集重試或長時間 sleep。不購買額度、不兌換重設券、不切換模型或帳戶。

但**週停止門檻優先於一般額度等待**：每次開始工作前及每個可驗證的工作階段之間，以 windowDurationMins 等於 10080 辨識適用 bucket 的週視窗，不假定它固定在 primary 或 secondary。只要週 usedPercent 大於或等於上方保存的門檻（包含剛好等於），立即透過 automation_update 將本排程設為 PAUSED，保留其餘欄位，記錄並回報一次「週用量已達停止門檻」與目前比例；不開始下一階段、不保持每 5 分鐘檢查、不安排自動重新啟用。停用失敗就明確回報，不能說已成功停止。待使用者明確要求再次啟用後，重新檢查額度才接續。缺少週用量資料則不開始工作，不以零用量代替。此保護不能強制中斷已在執行的操作、精確保留固定百分比或限制其他任務用量。

確認仍有已授權且未完成的工作，且目前額度可用後，從實際中斷點接續。先確認上次操作結果，避免重複修改、提交或對外動作；進行一個可驗證的工作階段，依工作區規範更新紀錄，繼續完成原始目標。這個排程不增加原任務的權限，也不替使用者同意新的對外發送或發布。若需要使用者必要資訊或決策，停用這個排程並只問一次具體問題。

沒有新結果、仍等待額度或已知狀態未改變時保持安靜；只有實質進展、完成、首次出現的重要失敗或需要使用者行動時才通知。排程只處理本次列明的工作，不承接其他任務的新工作。
