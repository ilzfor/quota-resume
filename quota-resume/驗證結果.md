## 尚未驗證

- 沒有刻意消耗帳戶額度到 100%，也沒有等待完整五小時恢復。因此尚無「真實額度耗盡 → 原生排程喚醒 → 接續原工作」的實測證據。
- 沒有對實際任務建立 ACTIVE 排程；沒有驗證排程的模型執行或自動完成後停用行為。這部分由技能與保存的 prompt 約定，並非 Python 單元測試已證明。
- 新增的週門檻停用規則同樣尚未用真實任務越過 70% 來實測。單元測試驗證的是判斷器；停用排程需要後續執行的模型遵循保存的 prompt 並成功呼叫 automation_update。它不是帳戶硬性用量限制，不能保證恰好保留 30%。
- 官方文件確認同對話排程與分鐘頻率，但未在所查文件中確認額度耗盡時排程器的停用／重試政策。
- 不能保證零 token 等待、恢復瞬間觸發、App 關閉或電腦休眠時仍能工作，也不控制 `/goal` 的 UI 暫停狀態。

## 實際驗收方式

在你本來就要執行的長時間工作中，先啟用外掛並確認 App 回報排程 ACTIVE。之後若自然遇到額度耗盡，記錄用量恢復時間、下一次排程狀態、原任務是否真的繼續及完成後是否 PAUSED。不要為了驗收刻意浪費 token。若原生排程被自動停用，必須回報此限制並調整方案，不能把安裝成功當成完整驗收。
